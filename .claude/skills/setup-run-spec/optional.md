# 可选的约定

第 2 步按第 1 步查到的情况挑出适用的几项提议给用户，用户同意的在第 4 步做。每项开头写什么情况下用。

## 拆共享登记处

仓库里有并行的工单都要往里加一项的文件（命令登记表、构建目标列表、迁移编号、总入口）时：能拆成每项一个文件的提议拆开；拆不了的写进配置说明「常见的共享登记处」。

## union 合并

仓库里有各分支都往末尾加行的列表（日志索引、研究索引）时：在 `.gitattributes` 里写一行 `<文件> merge=union`。本地 `git merge` 和 `git rebase` 都按它自动合并两边追加的行（git 2.34 实测）；GitHub 网页上合并 PR 时是否也按它没有实测，PR 显示冲突就在本地合并。只用于只追加的列表：两边改了同一行时，union 会把两个版本都留下，不报冲突。

## 目录地图

放文档、脚本、研究的目录还没有 README 时：各建一个，一行一项写清是什么、什么时候读。核对地图和目录一致的检查，放进第 6 步建议的第一个 spec。

## 画图约定

文档里要画架构图、流程图时：把 [diagrams.md](diagrams.md) 放进文档目录，在 `AGENTS.md` 加一句"画图之前读 <路径>"。

## 画像的两个可选项

- **项目要求**：项目需要设计负责人主动补上某类专家判断时（视频工作室：导演和剪辑会做的判断；医学影像平台：病理专家会做的判断）。设计角色文档加一节「项目对设计负责人的要求」，一到三句。
- **预登记**：仓库有实验，以及预登记的指标、阈值规则、门槛或锁定集用法时。设计角色文档「工作流」的思路指针后加一句：分析规则只在看到受影响的结果之前修订。

## 验证入口

仓库有要实测的产物（页面、命令行、服务、视频），而工单的【实测】每次现写办法时：安装 `verification` 技能（安装命令加 `--skill verification`），开一张工程工单按它为主要产物生成 `docs/verification/<产物>/`，验收看它实跑一遍的证据。

## 执行会话放在后台

主会话是 Claude Code、用户想让它不依附终端时：`claude --bg -n <名字> --permission-mode <和平时相同的模式> "<开场白>"` 启动，`claude attach <名字>` 进入；在里面按 ← 回到会话列表、按 Ctrl+Z 回到 shell，会话都继续运行。`claude agents` 看有哪些会话，`claude logs <名字>` 看最近的输出，`claude stop <id>` 停下。权限模式要和平时一致，不一致时碰到确认就停下等人。后台会话在用户的终端里看不到，启动后把这几条命令告诉用户。以上命令按 Claude Code 2.1.312 的 `--help` 核对。
